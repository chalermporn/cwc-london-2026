สร้าง workflow agent เชิงรุกด้วย routines ใน Claude Code

Build a proactive agent workflow with Claude Code

ผู้พูด: Maya (applied AI team, Anthropic)

เหมาะกับ: นักพัฒนาที่ใช้ Claude Code อยู่และอยากให้รันเองโดยไม่ต้องดูแล cron/infra

routines คือฟีเจอร์ใน Claude Code ที่รัน session บน managed infrastructure ของ Anthropic เริ่มได้จาก schedule, GitHub event หรือ webhook ผู้พูดเดโมทำ routine อัปเดต docs อัตโนมัติ และให้กรอบตัดสินใจ 3 เรื่อง คือ trigger, context, steering

Routines run remote Claude Code sessions on managed infrastructure, triggered by schedule, GitHub events or webhooks. The talk demos a docs-automation routine and frames design as trigger, context, steering.

ประเด็นสำคัญ

  1. ปัญหาของ proactive agent ตอนนี้มี 3 ข้อ คือ ต้องตัดสินใจว่ารันที่ไหน (ไม่ควรรันบนเครื่องตัวเอง เพราะปิดเครื่องแล้วจบ ต้องจัดการ hosting, persistence, auth), ต้องคิดว่าจะ trigger เมื่อไหร่, และ headless session ดู/คุม/resume ลำบาก
  2. routine คือ automation ที่เปิด remote Claude Code session โดยกำหนดแค่ prompt, repo, connector และ trigger ที่เหลือ Claude Code จัดการ ทำงานบน managed infrastructure ไม่ผูกกับ laptop
  3. trigger มี 2 แบบ คือ time-based schedule และ event-based (GitHub events แบบ native หรือ POST ไป webhook/endpoint พร้อม payload เป็น context) ตัวอย่างเช่น ทำเมื่อ cut release หรือเมื่อ PR ที่ติด label "need docs" ถูก merge
  4. ทุก routine คือ Claude Code session ที่เปิดดู ถามต่อ steer และ resume ได้จาก web, CLI และ desktop
  5. กรณีศึกษาภายใน: weekly PR ของ Claude Code เพิ่ม 200% ตั้งแต่ต้นปี วิศวกรที่ดูแล docs จึงตั้ง routine ให้รีวิวสิ่งที่ merge เข้า main เทียบกับ docs repo แล้วเปิด PR อัปเดต docs ทุกสัปดาห์ ผ่านคำสั่ง /schedule
  6. ตัดสินใจ 3 เรื่อง: trigger (เมื่อไหร่), context (repo + connector เช่น Google Drive, Slack — context ที่ให้คือเพดานความสำเร็จ), steering (ทำให้ Claude ซื่อสัตย์)
  7. วิธี steer: agent-on-agent review (routine หนึ่งสร้าง PR อีก routine รีวิวก่อนคน), เข้าไปดู/ถามกลางทางจาก Claude Code บนเว็บ, และ verify output เช่น render หน้า docs ที่แก้
  8. เดโมที่สอง: routine trigger จาก GitHub issue opened ที่สืบสวนว่าเป็น docs gap หรือไม่ ถ้าใช่เปิด PR และ ping Slack ผู้พูดสั่งหยุด session กลางทางเพราะมี PR อยู่แล้ว เพื่อโชว์การ steer แบบ real time

ลำดับขั้นที่ทำในคลิป

  1. เปิด Claude Code ใน terminal แล้วพิมพ์ /schedule ตามด้วยคำสั่ง เช่น ทุกสัปดาห์ให้รีวิวสิ่งที่ merge เข้า main เทียบกับ docs repo แล้วสร้าง PR ถ้ามีการเปลี่ยนแปลง
  2. ตอบคำถามที่ Claude ถามกลับ เช่น เวลาที่ให้รัน และจะแจ้งเตือนทาง Slack ไหม
  3. Claude สร้าง routine และ instructions ให้ ไปดูได้ที่ Claude Code บนเว็บ (claude.ai แท็บ Code แล้วเลือก routines)
  4. ตรวจ routine: เชื่อม 2 repo (source code กับ docs), รันทุกวันจันทร์ 10:00, ต่อ GitHub และ Slack
  5. เปิด session ที่รันแล้ว ดู Claude อ่านซอร์ส PR ที่ merge change log เทียบกับ docs แล้วเปิด PR
  6. สร้าง routine ใหม่ trigger จาก GitHub event ชนิด issue opened ต่อ docs repo, source repo, Slack และ GitHub MCP
  7. สร้าง issue ทดสอบ ดู run ใหม่ที่ได้ context จาก issue แล้ว steer ให้หยุด session
  8. ตัวอย่างต่อยอด: deploy verifier (CD pipeline POST ไป webhook, ต่อ Datadog/Grafana/Slack), on-call investigator, PM triage backlog รายสัปดาห์

ตัวเลข / ข้อเท็จจริงที่ผู้พูดบอก

ตามที่ผู้พูดอ้างในคลิป ไม่ได้ยืนยันกับแหล่งอื่น

  • weekly PRs ของ Claude Code เพิ่มขึ้น 200% ตั้งแต่ต้นปีใหม่ ตามที่ผู้พูดบอก
  • routine ตัวอย่างรันทุกวันจันทร์ 10:00 น. เชื่อม GitHub และ Slack
  • trigger มี 2 ประเภทหลัก: schedule และ event (GitHub native หรือ webhook POST)

สิ่งที่นำไปทำต่อ

  • ลองหา task ประจำวันที่เปลี่ยนเป็น routine ได้ แล้วเริ่มด้วย /schedule
  • ก่อนสร้างทุก routine ตอบ 3 ข้อ: trigger อะไร, context อะไรที่ต้องให้, steer อย่างไร
  • ให้ routine ที่สร้างงาน กับ routine ที่รีวิวงาน แยกกัน
  • เริ่มจาก human-in-the-loop (agent วิเคราะห์ คนตัดสิน) แล้วค่อยเพิ่มสิทธิ์เมื่อไว้ใจ
  • ทุกเอาต์พุตควร verify ได้ เช่น render หน้า docs

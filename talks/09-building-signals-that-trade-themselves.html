Man Group: governed skills ทำให้ AI สร้างสัญญาณเทรดที่ใช้เงินจริงได้

Building signals that trade themselves

ผู้พูด: Sharan Fernando (Head of data and AI, Man Group (ชื่อตาม caption; คำอธิบายคลิปเขียน 'Tushara Fernando'))

เหมาะกับ: เหมาะกับคนที่ต้องพา AI เข้าองค์กรที่มี compliance เข้มและอยากรู้ว่า governance ของ skills ควรหน้าตาเป็นอย่างไร

Man Group (ผู้จัดการกองทุนทางเลือก) เล่าว่ามีสัญญาณเทรดที่ AI คิดไอเดีย ดึงข้อมูล backtest และเขียนข้อเสนอ รันด้วยเงินจริงแล้ว โดยมีมนุษย์รีวิว ตัวเปิดทางคือ skills ที่ผ่าน governance ไม่ใช่การเทรนโมเดลใหม่ ข้อสรุปคือ skill ต้องมีเจ้าของที่เป็นเจ้าของ workflow จริง มี eval รีวิว และ lifecycle เหมือน production code

Man Group says trading signals researched, backtested and proposed by AI are running real capital, enabled by a governed skills marketplace rather than retraining. Skills need workflow owners, evals, review and lifecycle like production code.

ประเด็นสำคัญ

  1. Man Group บริหารสินทรัพย์เกิน 200 พันล้านดอลลาร์ ลูกค้าเป็นกองทุนบำนาญและกองทุนความมั่งคั่ง ผู้พูดจึงบอกว่าความเสี่ยงสูงถ้า AI ผิดพลาด ธุรกิจหลักส่วนหนึ่งคือ systematic trading ที่ตัดสินใจจากสัญญาณข้ามหลักทรัพย์จำนวนมาก
  2. ผู้พูดเปรียบสัญญาณเทรดกับทีมแฟนตาซีฟุตบอล: จัดอันดับหุ้นด้วย factor (เช่น ผลตอบแทน 3 เดือน) แล้วทดสอบย้อนหลังด้วย backtest ดูตัวชี้วัดอย่างผลตอบแทนต่อปี drawdown และ Sharpe ratio
  3. ผู้พูดบอกว่ามีสัญญาณที่ AI คิดไอเดีย หาข้อมูล รัน backtest เขียนข้อเสนอ และทำเป็น production ซึ่งรันด้วยทุนจริงอยู่ตอนนี้ โดยมนุษย์รีวิวผลทั้งหมด แต่ไม่เปิดเผยว่าเป็นสัญญาณอะไร เพราะเป็น IP
  4. สัญญาณเป็นแค่ยอดภูเขาน้ำแข็ง ใต้น้ำคือ workflow (ล้างข้อมูล, ต่อราคา, จับ outlier, infra, backtest) ถ้าแต่ละทีมใช้ workflow คนละเวอร์ชัน ผลจะเทียบกันไม่ได้ จึงต้องมีฐานร่วม
  5. สอน Claude ด้วยการให้เข้าถึงข้อมูล ความสามารถ และ workflow ขององค์กร ไม่ใช่ fine-tuning โดย skills เป็นชั้นเชื่อม
  6. บทเรียนความผิดพลาด: รอบแรกเน้น adoption (workshop, hackathon, show-and-tell) ได้คนเขียน skill เยอะ แต่ส่วนใหญ่เป็น power user ไม่ใช่เจ้าของ process ตัวอย่างคือ skill ทำใบเบิกค่าใช้จ่ายที่ hardcode cost center ทำให้ผู้อนุมัติฝ่ายขายได้รับรายงานของแผนกอื่น
  7. ทางแก้: marketplace กลาง (Man a knowledge) ที่ทุก skill มองเห็นได้ มี tag มีเจ้าของคือ workflow owner ทดสอบด้วย evals ติดตามการใช้งาน รีวิว และมี lifecycle เดโมแสดงการค้นหา alternative data (credit card data) ใช้ 4 skills สร้างสัญญาณเบื้องต้นแล้วรัน backtest บน compute แบบกระจาย
  8. บทเรียนปิดท้าย: organizational context คือ moat, ปฏิบัติต่อ skills เหมือน production code, วางแผนเจ้าของ/รีวิว/ปลดระวางก่อน rollout, และ adoption เป็นปัญหาของคน ไม่ใช่ license

ตัวเลข / ข้อเท็จจริงที่ผู้พูดบอก

ตามที่ผู้พูดอ้างในคลิป ไม่ได้ยืนยันกับแหล่งอื่น

  • Man Group บริหารสินทรัพย์เกิน 200 พันล้านดอลลาร์ (ตามที่ผู้พูดบอก)
  • Backtest รันบนประวัติศาสตร์ 15 ปี หรือนานกว่า
  • ใช้ Claude Code 750 คน จากพนักงานราว 17,800 คน (ผู้พูดพูดทั้ง 17,800 และ 1,700 ในประโยคเดียว จึงไม่แน่ใจ)
  • มี governed skills เกิน 100 ตัว และ community skills อย่างน้อยเท่ากัน
  • เดโม: ลงทุน $1,000 ในปี 2021 ตามสัญญาณ credit card จะเป็นราว $2,500 สำหรับ Amazon (ผู้พูดบอกเองว่าอาจเป็นความบังเอิญ จึงรันกับกลุ่มค้าปลีกเพิ่ม)
  • เคสเดโมใช้ 4 skills สร้างสัญญาณ

ประโยคเด่น (ต้นฉบับ)

“Treat those skills like production code because that's what they will become.”

ปฏิบัติต่อ skills เหมือนโค้ด production เพราะสุดท้ายมันจะกลายเป็นอย่างนั้น

“Adoption is not a licensing problem. It's a people problem.”

การนำไปใช้ไม่ใช่ปัญหาเรื่องไลเซนส์ แต่เป็นปัญหาของคน

“The work is on exposing it, not reinventing it.”

งานคือเปิดเผยบริบทที่มี ไม่ใช่คิดใหม่

สิ่งที่นำไปทำต่อ

  • ก่อนปล่อย skill ตัวแรก ตกลงให้ชัดว่าใครเป็นเจ้าของ ใครรีวิว ทดสอบอย่างไร และปลดระวางเมื่อไร
  • ให้เจ้าของ workflow จริงเป็นคนถือ skill ไม่ใช่ power user ที่ใช้บ่อยที่สุด และอย่า hardcode ค่าเฉพาะบุคคล เช่น cost center
  • รวม skills ไว้ใน marketplace กลางที่ tag ค้นหาได้ ติดตามการใช้ และมี eval
  • เริ่มจากการเปิดเผยข้อมูลและ workflow ที่องค์กรมีอยู่ให้ Claude เข้าถึง แทนการเทรนโมเดล
  • วางแผนด้าน training และ engagement เพราะการรับไปใช้เป็นเรื่องของคน

ข้อควรระวังในสรุปนี้

  • ชื่อผู้พูดไม่ชัด: caption เขียน 'Sharan Fernando' แต่คำอธิบายคลิปเขียน 'Tushara Fernando' ควรตรวจกับแหล่งทางการ
  • ผู้พูดไม่เปิดเผยตัวสัญญาณหรือผลตอบแทนจริง ข้ออ้างว่ามี signal รันเงินจริงจึงตรวจสอบไม่ได้จากคลิป
  • ตัวเลขพนักงาน (17,800 กับ 1,700) ฟังจาก ASR ไม่ชัด และตัวเลข $2,500 มาจากเดโมแบบง่าย ผู้พูดบอกเองว่าจริงซับซ้อนกว่า
  • ชื่อแพลตฟอร์มภายใน 'Man a knowledge' ตาม caption อาจสะกดเพี้ยน
  • ไม่ใช่คำแนะนำการลงทุน เป็นกรณีศึกษาเรื่อง governance ของ skills

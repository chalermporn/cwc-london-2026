Metaview ทำ prompt คัดใบสมัครให้เรียนรู้จากการตัดสินใจของ recruiter เอง

How Metaview built self-improving prompts for application review

ผู้พูด: Nick Mayhew (Product Engineer, Metaview)

เหมาะกับ: คนสร้างระบบ evaluation หรือ agent ที่ผู้ใช้เป็นคนตัดสินใจ และอยากรู้ว่าจะให้ prompt พัฒนาตามพฤติกรรมผู้ใช้ได้อย่างไร

Metaview สร้างระบบคัดใบสมัครที่ไม่ตั้งเกณฑ์ตายตัว แต่ให้ agent สังเกตว่า recruiter ผ่านหรือปัดใคร แล้วปรับ Ideal Candidate Profile (ICP) ซึ่งเป็น markdown prompt ให้ทันความต้องการที่เปลี่ยนไป ข้อสรุปคือ preferences ของผู้ใช้เปลี่ยนเสมอ ให้เขียนเป็นร้อยแก้วไม่ใช่กฎ และฝัง guardrail ในสถาปัตยกรรมให้ระบบเป็นแค่ apprentice

Metaview's application review keeps an Ideal Candidate Profile prompt up to date by watching recruiter decisions; design rules: expect preferences to evolve, use prose not rules, and build guardrails in so the system stays the apprentice.

ประเด็นสำคัญ

  1. ผู้พูดบอกว่าตั้งแต่ปี 2023 LLM ทำให้ใบสมัครงานเพิ่มพรวด ผู้สมัครใช้ AI ช่วยเขียน recruiter จึงต้องการตัวช่วยคัดกรอง
  2. ปัญหาแกนกลางคือเกณฑ์ของ hiring manager เปลี่ยนไปเรื่อยๆ (เช่น เพิ่งบอกว่าอยากได้ประสบการณ์ startup แล้วค่อยเพิ่ม zero-to-one) ถ้า prompt เป็นกฎที่ตั้งไว้ล่วงหน้า ต้องเขียนใหม่ทุกรอบ จึงต้องวางให้ prompt เปลี่ยนตาม preferences ตั้งแต่ฐานระบบ
  3. ขั้นตอน: ลบข้อมูลระบุตัวตนของผู้สมัคร (ชื่อ อีเมล เบอร์) แล้วจับคู่กับ ICP เพื่อสร้างผลประเมิน ส่วน ICP คือ prompt ที่เรียนรู้และปรับตัวเอง
  4. หลักคิดคือ human in the center ไม่ใช่แค่ in the loop: ระบบเป็น apprentice ช่วยงานหนักและชี้ข้อสังเกต ส่วนการผ่านหรือปัดผู้สมัครเป็นของ recruiter เสมอ
  5. ICP agent รับ user messages (ผ่าน ปัด feedback แก้ ICP ด้วยมือ) และเพราะ feedback เป็นเชิงเปรียบเทียบกับสิ่งที่เพิ่งเห็น จึงมี tool เฉพาะชื่อ query files ไว้ไล่ resume ที่ลบข้อมูลตัวตนแล้ว เพื่อตีความคำอย่าง 'Python น้อยไป' ก่อนส่งให้ ICP manager agent ที่มีหน้าที่เดียวคือรักษา prompt ให้ทันสมัย
  6. ทำไมเป็น workflow ที่มี agent ครอบอยู่ข้างบน: ปริมาณพันๆ ใบสมัครต่อวันรับต้นทุนไม่ไหวถ้าโยนทุกอย่างให้ agent จึงต้องประหยัด token
  7. ICP เป็นเอกสาร markdown ภาษาธรรมชาติ (role summary, must haves, nice to haves, red flags) ไม่ใช้ weighting หรือ if-statement เพราะ recruiter คิดและเขียนแบบนั้น และ LLM เก่งภาษา
  8. เลือกโมเดล: Haiku ทำ evaluation ปริมาณสูง Sonnet ทำงานหาแพตเทิร์นที่ latency สำคัญน้อยกว่า ผู้พูดว่าใช้โมเดล Claude เพราะต้องการตัวที่คิดเชิงวิพากษ์ ไม่เชื่อ fluff ใน CV ตามคำผู้พูด ในเดโมเห็น Sonnet 4.6 เรียก tool อัปเดต ICP แล้วแสดง diff สีเขียวแดงให้ผู้ใช้ยืนยันหรือแก้

ตัวเลข / ข้อเท็จจริงที่ผู้พูดบอก

ตามที่ผู้พูดอ้างในคลิป ไม่ได้ยืนยันกับแหล่งอื่น

  • ลูกค้ารายหนึ่งได้ 2,740 ใบสมัครสำหรับงานเดียวใน 24 ชั่วโมง (ผู้พูดบอกว่าเกิดบ่อยกับงาน remote ระดับ junior)
  • คำตอบของคำถามในใบสมัคร (เช่น ทำไมอยากทำงานที่นี่) ยาวขึ้นราว 50% ในสองปีที่ผ่านมา ตามที่ผู้พูดบอก
  • โมเดลที่ใช้: Haiku สำหรับ evaluation, Sonnet สำหรับ ICP agent (ในเดโมเห็น Sonnet 4.6)
  • ผู้พูดบอกว่าปกติเริ่มเห็นแพตเทิร์นทุก 100-200 ครั้ง จึงไม่ปรับ ICP จาก feedback ครั้งเดียว
  • ประมวลผลหลายพันใบสมัครต่อวัน และมี input per token limit พิเศษจาก Anthropic ตามคำผู้พูด

ประโยคเด่น (ต้นฉบับ)

“Make the user the master and make the system the apprentice.”

ให้ผู้ใช้เป็นนาย และให้ระบบเป็นลูกมือ

“Allow them to reason in prose, not in flow charts.”

ให้ LLM คิดเป็นร้อยแก้ว ไม่ใช่ flow chart

“Lean into what LLMs are good at, which is natural language.”

ใช้จุดแข็งของ LLM คือภาษาธรรมชาติ

สิ่งที่นำไปทำต่อ

  • ถ้าระบบให้ผู้ใช้เป็นคนตัดสินใจ ให้ถือว่า preferences จะเปลี่ยนแน่ และออกแบบกลไกอัปเดต prompt ตั้งแต่วันแรก
  • เก็บเกณฑ์ประเมินเป็นเอกสารภาษาธรรมชาติที่ผู้ใช้อ่านและแก้เองได้ แทน weighting หรือ if-statement
  • แสดงการเปลี่ยน prompt เป็น diff ให้ผู้ใช้ confirm หรือแก้ก่อนมีผล และอย่าอัปเดตจากตัวอย่างเดียว รอให้เห็นแพตเทิร์น
  • แยกงานปริมาณสูงที่ต้องถูกและเร็ว (โมเดลเล็ก) ออกจากงานหาแพตเทิร์นที่ใช้ความฉลาด (โมเดลใหญ่)
  • ฝัง guardrail ในสถาปัตยกรรม ให้ระบบช่วยและแนะนำ แต่ไม่ overrule ผู้ใช้

ข้อควรระวังในสรุปนี้

  • transcript มาจาก Whisper large-v3 ที่ถอดเอง ชื่อเฉพาะอาจเพี้ยน เช่น 'clored models' = Claude models, 'Langchain/LandGraph' = LangChain/LangGraph, 'UPSA ICP tool' น่าจะเป็น upsert ICP tool
  • ช่วงเล่าเรื่อง feedback เชิงเปรียบเทียบใน ICP agent มีประโยคซ้ำวนและขาดความหมายในไฟล์ จึงสรุปจากส่วนที่ชัดเท่านั้น
  • ตัวเลข 2,740 และ 50% เป็นข้ออ้างของผู้พูด ไม่มีแหล่งอ้างอิงในคลิป
  • ผู้พูดบอกว่ายังโต้เถียงกับตัวแทน Anthropic เรื่อง Claude Managed Agents ปัจจุบัน deploy บน LangChain/LangGraph

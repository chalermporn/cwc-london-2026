Claude Managed Agents: ให้แพลตฟอร์มดูแลโครงสร้าง agent แล้วไป production ได้เร็วขึ้น

How to get to production faster with Claude Managed Agents

ผู้พูด: Michael (member of technical staff, Anthropic (Claude Managed Agents)); Harrison (member of technical staff, Anthropic (Claude Managed Agents)); Mike (Cloudflare (ผู้ร่วมเสวนา)); Yvon (Daytona (ผู้ร่วมเสวนา ชื่อสะกดจาก ASR)); Akshat (Modal (ผู้ร่วมเสวนา ชื่อสะกดจาก ASR)); Luke (Vercel (ผู้ร่วมเสวนา))

เหมาะกับ: นักพัฒนาที่จะ deploy agent จริงและอยากรู้ว่า Managed Agents จัดการอะไรให้ รวมถึงคนสนใจ sandbox/โครงสร้างพื้นฐานของ agent

ทีม Managed Agents อธิบายว่าคอขวดของ agent ตอนนี้คือโครงสร้างพื้นฐานรอบโมเดล ไม่ใช่ความฉลาด Managed Agents จึงให้ primitive สำเร็จรูป (agent, environment, session, event stream) พร้อมฟีเจอร์ขั้นสูง เช่น multi-agent, outcomes, memory, dreaming, self-hosted sandboxes และ MCP tunnels แล้วปิดด้วยเสวนากับ Cloudflare, Daytona, Modal, Vercel เรื่องการรัน sandbox ระดับใหญ่

Managed Agents packages agent infrastructure into primitives (agent, environment, session, event stream) with advanced features like outcomes, memory, dreaming, self-hosted sandboxes and MCP tunnels; a partner panel discusses sandbox fleets.

ประเด็นสำคัญ

  1. ผู้พูดเล่าเส้นทางความสามารถจาก Claude 3 ที่ทำงานสั้นๆ, Opus 4 ที่ Claude Code ขับทั้ง feature ได้, จนถึง Opus 4.7 ที่คนเคลียร์ backlog ทั้งก้อนแล้วตื่นมาเจอ PR พร้อม merge และมองว่างานระดับทั้งไตรมาสจะเสร็จในไม่กี่ชั่วโมง เช่น M&A pipeline ด้วย agent team
  2. ผู้พูดบอกว่าคอขวดตอนนี้คือโครงสร้างพื้นฐานรอบโมเดล ไม่ใช่ความฉลาด จากการวิจัยพบ 3 จุดติด คือ context management/memory, infrastructure (reliability, scalability, security, latency ซึ่งถูกอ้างเป็นตัวขวางอันดับหนึ่ง) และ observability
  3. agent ต้องการ credential ที่ปลอดภัย การเข้าถึงระบบภายใน และ identity/auth ของตัวเอง รวมถึงรูปแบบการใช้งานที่เปลี่ยนจากแชตตอบกลับ ไปเป็น outcome-oriented และการเริ่มงานแล้วกลับมาทำต่อทีหลังเป็นสัปดาห์หรือเดือน
  4. เริ่มใช้ 4 ขั้น: (1) define agent = system prompt, model, skills, tools, permissions (2) สร้าง environment/sandbox กำหนด network allow list และ package (3) เริ่ม session สั่งงาน (4) ฟัง event stream เพื่อดูและโต้ตอบ
  5. event stream แบ่ง 4 กลุ่ม: user events (ข้อความ, รูป, เอกสาร, interrupt, tool result ของ custom tool, human-in-the-loop confirmation, outcome definition), agent events (ตอบ, เรียก tool, ประสานกับ agent อื่น), session events (สถานะ idle/running, error recovery, outcome processing) และ span events (บอกจุดเริ่ม/จบของงานยาวๆ)
  6. เดโมคอนโซลกับ agent สมมติชื่อ Pascal วิเคราะห์พฤติกรรมซื้อของชำ: เห็น event แบบ real time, ดู system prompt/model/MCP config ฝั่งขวา, ดู network กับ package ของ environment ทั้งหมดเปิดผ่าน API และมีปุ่ม Ask Claude ให้ Claude อ่าน transcript แล้วแนะนำการปรับ config เช่น Python script ที่ใช้เวลาเกิน 20 วินาที
  7. ทางเริ่มต้นที่แนะนำ: Claude API skill ใน Claude Code ที่รู้เรื่อง managed agents, CLI สำหรับคุม agent/session และ cookbooks ที่ copy ไปใช้ได้
  8. ฟีเจอร์ขั้นสูง: multi-agent orchestration (spawn agent thread ที่มี context window ของตัวเอง), outcomes (กำหนด rubric ให้ Claude วนปรับจนพอใจ), memory, dreaming (research preview) และที่ประกาศในงาน: self-hosted sandboxes (ใช้ compute ของตัวเองใน VPC โดย Anthropic ส่งสัญญาณเมื่อต้องการ sandbox ใหม่) กับ MCP tunnels (research preview เปิด private MCP server ให้ Claude โดยไม่ต้องเปิด public internet)
  9. เสวนากับพาร์ตเนอร์ sandbox: Vercel ใช้พื้นฐานเดียวกันให้ build/sandbox/function (fluid compute) และมี firewall ฉีด secret ได้, Modal เน้น scale (หลักแสน sandbox ในไม่กี่นาที), GPU และหลาย region, Daytona เน้นว่า agent ต้องการสิ่งเดียวกับมนุษย์ (spec ต่างๆ, pause/resume/fork), Cloudflare มี micro VM กับ isolate ที่เบากว่า
  10. ความท้าทายที่ผู้ร่วมเสวนาพูดถึง: security ตอน deploy (egress filtering, การกำหนด identity ตลอดสายเมื่อ agent สร้าง agent), permission ของ agent เทียบกับมนุษย์, การ resume งาน, และการทำงานแบบ multiplayer ที่ agent ยังเป็น single-player ส่วนที่ตื่นเต้น เช่น chief of staff ส่วนตัวให้ทุกคน, ให้ Claude hill-climb inference ด้วย profiler บน GPU sandbox, human emulator ที่ใช้ sandbox เข้าแอป legacy

ลำดับขั้นที่ทำในคลิป

  1. Define agent: system prompt, model, skills, tools, permissions, identity
  2. สร้าง environment: sandbox พร้อม network allow list และ package ที่ติดตั้งไว้
  3. เริ่ม session แล้วสั่งงาน ให้ agent กลับมาหาเมื่อเสร็จ
  4. ฟัง event stream (user/agent/session/span events) เพื่อสังเกตและโต้ตอบ เช่น interrupt, ส่ง tool result, ยืนยัน human-in-the-loop
  5. เดโม Pascal: กดปุ่ม analyze ใน dashboard ของแอป -> ดู event และ config ใน console -> แอปแสดงผลผ่าน API -> สั่ง predictive analysis -> กด Ask Claude เพื่อให้ Claude อ่าน transcript แล้วแนะนำการปรับ config
  6. เริ่มพัฒนา: ใช้ Claude API skill ใน Claude Code, CLI และ cookbooks

สิ่งที่นำไปทำต่อ

  • ก่อนสร้าง agent platform เอง ลองดูว่า primitive ของ Managed Agents (agent/environment/session/event stream) ครอบสิ่งที่ต้องทำเองอยู่แล้วแค่ไหน
  • ใช้ event stream เป็นฐานของ observability และ UI ของแอปตัวเอง ไม่ต้องสร้าง logging แยก
  • ถ้าข้อมูลหรือเครื่องมือต้องอยู่ใน VPC ให้พิจารณา self-hosted sandboxes กับ MCP tunnels แทนการเปิด public endpoint
  • ใช้ outcomes (rubric) กับ multi-agent สำหรับงานที่ต้องวนปรับเอง และเปิด memory/dreaming สำหรับงานซ้ำ
  • เริ่มด้วย Claude API skill ใน Claude Code กับ cookbooks เพื่อต่อ API ได้เร็ว

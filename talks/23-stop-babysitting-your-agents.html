เลิกเฝ้า agent: verification loop, multi-Claude และงานเบื้องหลัง

Stop babysitting your agents

ผู้พูด: Sid Bidisaria (สะกดตาม Whisper อาจเพี้ยน) (founding engineer ของ Claude Code)

เหมาะกับ: คนที่ใช้ Claude Code ทุกวันและอยากได้ระดับ advanced ควรมี CLAUDE.md และต่อ tool เข้า Claude Code มาก่อนแล้ว

ผู้พูดจาก Claude Code team บอกว่าโมเดลเก่งขึ้นแต่คนยังต้องเฝ้าหน้าจอและนั่งเป็น QA ให้ Claude ทางออกคือสอน Claude ให้ verify งานตัวเองเป็น loop (รัน app, ใช้ browser, พิสูจน์ผล, ปลดบล็อก auth/state) แล้วเก็บไว้เป็น skill ที่แก้ตัวเองได้ จากนั้นขยายเป็นหลาย session และงานเบื้องหลัง

A Claude Code founding engineer shows how to stop babysitting: give Claude a verification loop (run app, drive browser, prove result, unblock auth/state), package it as a self-improving skill, then scale with desktop app, Claude Agents, web and Remote Control.

ประเด็นสำคัญ

  1. ผู้พูดตั้ง 3 ข้อพื้นฐาน: CLAUDE.md คุณภาพสูง (ตามคำเขา เป็นสิ่งที่ leverage สูงสุด), ต่อ tool ที่ใช้ในชีวิตจริงให้ Claude (Slack, Asana, Linear, Datadog, BigQuery) และตั้ง remote environment บน Claude Code Web ให้ compute แยกจากแล็ปท็อป
  2. tooling เดิมสร้างมาเพื่อคน แต่ตอนนี้ agent เป็นคนเขียนโค้ดส่วนใหญ่ จึงต้องถามว่า agent ต้องการอะไรจาก codebase ที่คนมองข้ามไปเพราะคิดว่าเป็นเรื่องปกติ
  3. verification loop คือหัวใจ: Claude เขียนโค้ด เช็คว่า fail ไหม debug แล้วเขียนต่อวนจนสำเร็จ ตัวอย่างคือแก้ปุ่ม sign-up เว็บส่วนตัว Claude build app คลิกปุ่มใน browser อ่าน log แก้ แล้วส่ง PR ที่ทำงานจริง
  4. ผู้พูดบอกว่าการให้ tool และคำสั่งสำหรับ loop ลงที่ 4 อย่าง: รัน application (เช่น dev server), ให้ Claude ใช้ app ผ่าน browser (Claude in Chrome ผ่าน /chrome หรือ Playwright), พิสูจน์ผล (screenshot ก่อน/หลังแก้) และปลดบล็อก auth กับ state ด้วย script ที่ไม่ตายตัวเกินไป
  5. เก็บ loop เป็น skill แล้วทำให้ self-improving: สั่งให้ skill แก้ตัวเองทุกครั้งที่เจอ blocker ทีม Claude Code ใช้ verification skill เดียวที่ถูกสั่งให้บันทึกตัวเอง ทุกคนในทีมช่วยกันเติม
  6. เดโมกับ MonkeyType: สั่งเปิด dev server, ใช้ Chrome MCP ตรวจ front end พิมพ์ทดสอบ เปลี่ยน settings แล้วสั่งสรุปเป็น skill file จากนั้นเพิ่มฟีเจอร์ confetti ตอนพิมพ์ผิดโดยให้ Claude ใช้ skill นั้น verify ตัวเอง (เปิด auto mode) Claude แก้ lint error เองจนผ่าน
  7. ขยายหลาย session: ผู้พูดบอกว่าเกิน 4-5 session สมองเริ่มรับไม่ไหว เครื่องมือช่วยจัดการความสนใจคือ desktop app (sidebar รวมทุก session, pin/rename/ใส่สี), Claude Agents (เรียงตามระดับที่ต้องการความสนใจ), Claude Code on the web และ Remote Control (/remote-control สั่งจากมือถือ มี notification)
  8. ช่วงสุดท้ายเรื่อง background loops: งานแบบเฝ้า PR (review comment, merge conflict, CI fail), อัปเดต docs, triage, monitor feedback และรักษา CI ให้เขียว ควรโยนให้ Claude ทำเบื้องหลัง

ลำดับขั้นที่ทำในคลิป

  1. เตรียม app ไว้ในเครื่อง ติดตั้ง dependencies และมี CLAUDE.md (MonkeyType: Express + MongoDB + Redis)
  2. เปิด session ใหม่ สั่งให้ Claude spin up dev server แล้วเปิด front end/back end ตรวจเอง
  3. เปิด Chrome MCP ด้วย /chrome (ตรวจว่า status enabled, extension installed)
  4. สั่ง 'use the Chrome MCP to make sure the front end is working' แล้วไล่ให้ลองพิมพ์ และเปลี่ยน settings (ตั้ง difficulty เป็น Expert แล้วเช็คว่าค่าถูกเก็บ) ดู tool call ด้วย Ctrl-O
  5. สั่ง 'take everything we learned and put it into a skill file' ได้ SKILL.md: ขั้น bring up the stack (Docker Compose), โหลด Chrome MCP tools, smoke test ด้วย browser
  6. เปิด auto mode แล้วสั่งเพิ่มฟีเจอร์ confetti เมื่อพิมพ์ผิด พร้อมให้ใช้ skill ที่สร้าง verify งานตัวเอง
  7. ดู loop ทำงาน: Claude เขียนโค้ด เจอ lint error แก้ แล้ว verify ซ้ำ จนเห็น confetti จริง

ตัวเลข / ข้อเท็จจริงที่ผู้พูดบอก

ตามที่ผู้พูดอ้างในคลิป ไม่ได้ยืนยันกับแหล่งอื่น

  • ผู้พูดบอกว่าเปิดเกิน 4-5 session พร้อมกันแล้วภาระสมองสูงเกินไป
  • การตั้ง verification loop เองใช้เวลาประมาณ 5-10 นาที (ตามที่ผู้พูดประเมิน)
  • องค์ประกอบ verification loop 4 อย่าง: run app / use via browser / prove it works / unblock (auth, state)
  • ช่องทาง multi-Claude 4 แบบ: desktop app, Agent view (Claude Agents), Claude in the cloud, Remote Control
  • Claude Agents ปล่อยมาประมาณหนึ่งสัปดาห์กว่า ณ วันที่พูด (ตามผู้พูด)
  • demo app: MonkeyType เขียนด้วย TypeScript + Express backend, MongoDB และ Redis

“The key takeaway here is you should try to hold Claude's hand and show it how to do verification.”

ข้อสรุปหลักคือให้จูงมือ Claude สอนวิธี verify

สิ่งที่นำไปทำต่อ

  • ก่อนเรื่องอื่น ตรวจให้ครบ 3 ข้อ: CLAUDE.md ดี, ต่อ tool, ตั้ง remote environment
  • ลองจูงมือ Claude ทำ verify ครั้งเดียว (รัน app, ใช้ browser, เช็คผล) แล้วสั่งให้สรุปเป็น skill ทันที
  • ใส่คำสั่งใน skill ให้อัปเดตตัวเองเมื่อเจอ blocker แล้วแชร์ในทีม
  • ถ้าเปิดหลาย session ให้ใช้ Claude Agents หรือ desktop app จัดตามระดับที่ต้องการความสนใจ และตั้ง /remote-control ไว้รับ notification จากมือถือ
  • ระบุงาน bookkeeping ที่เสียเวลา (เฝ้า PR, docs, CI) เพื่อโยนให้ background loop

ข้อควรระวังในสรุปนี้

  • transcript ช่วงท้ายเสียหาย: มีประโยคซ้ำวน (Whisper loop) ช่วง Claude Code desktop ต่อด้วย Claude Agents และช่วง background automation ซึ่งเป็นหัวข้อสุดท้ายถูกตัดเหลือเพียงรายการงานทั่วไป ไม่มีรายละเอียดวิธี implement
  • ในส่วน verification loop ผู้พูดบอกว่ามี 4 อย่าง แต่ transcript มีรายละเอียดเฉพาะแนว front-end เท่านั้น

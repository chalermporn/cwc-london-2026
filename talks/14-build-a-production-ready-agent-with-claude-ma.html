สร้าง agent พร้อม production ด้วย Claude Managed Agents (เดโม Deal Desk)

Build a production-ready agent with Claude Managed Agents

ผู้พูด: ไม่ได้ระบุชื่อใน transcript

เหมาะกับ: นักพัฒนาที่อยากเริ่มสร้างผลิตภัณฑ์บน Managed Agents API รู้ TypeScript/SDK เบื้องต้นก็พอ

เวิร์กชอปพาเขียนเว็บแอป Deal Desk ที่ต่อกับ Claude Managed Agents ผ่าน SDK ตั้งแต่ list session ไปจนถึง chat view และ outcomes แล้วไล่ดู multi-agent แบบ live ใน developer console ผู้พูดสรุปว่าของที่ต้องสร้างเอง (agent loop, sandbox, durable storage, auth) Managed Agents ให้มาพร้อมใช้

A hands-on session building a Deal Desk web app on Claude Managed Agents: list/retrieve sessions, chat via events and streaming, outcomes, multi-agent threads, and live debugging in the console. The speaker argues Managed Agents replaces the agent loop, sandbox fleet, storage and auth you would otherwise build.

ประเด็นสำคัญ

  1. Managed Agents คือชุด API endpoint ที่ใช้ได้ด้วย API key ทั่วไป ให้ primitive สำหรับ agent พร้อม production เช่น เครื่องคอมพิวเตอร์ให้ Claude, credential vault, tool harness, retry/error recovery, memory, context management และ multi-agent เลือกใช้เฉพาะชิ้นที่ต้องการได้
  2. building block หลักมี 4 อย่าง คือ agent (เหมือน template: system prompt, skills, tools, MCP servers, permission ต่อ tool เช่น file read auto-execute แต่ bash ต้องให้ผู้ใช้อนุมัติ), environment (template ของ sandbox: network access, pre-install package จาก npm/pip), session (บทสนทนาต่อเนื่อง ใส่ GitHub repo หรือไฟล์ล่วงหน้าได้) และ events
  3. events แบ่งเป็น user events (ข้อความ รูป เอกสาร interrupt tool result confirmation และ outcomes), agent events (ข้อความ compaction tool call multi-agent coordination), session events (สถานะ retry error idle terminate รวมถึง outcome processing) และ span events (บอกจุดเริ่ม/จบของงานยาว)
  4. outcomes คือการส่งไฟล์หรือข้อความที่เขียนเป็น spec/rubric ให้ Claude ทำรอบแรก แล้วเข้าโหมดวนตรวจงานตัวเองกับ rubric จนผ่าน ผู้พูดบอกว่าพบว่าทรงพลังมากและเป็นวิธีตั้ง agent ให้สำเร็จ
  5. ประกาศวันเดียวกัน คือ self-hosted sandboxes (ใช้ Cloudflare, Modal, Vercel หรือ fleet ของตัวเอง เก็บข้อมูลไว้ใน VPC/perimeter) และ MCP tunnels (secure tunnel ไป private MCP server โดยไม่ต้องเปิดออก internet)
  6. เดโม Deal Desk เป็นแอปสมมติสำหรับตัดสินใจลงทุน/ซื้อกิจการ ใช้ multi-agent ที่เปิดตัวเมื่อ 2 สัปดาห์ก่อน มี agent หลายตัวคนละ persona (เช่น macro trends กับ financial analysis) ต่อ Linear MCP และไฟล์ที่อัปโหลด
  7. ฝั่งโค้ด เริ่มจาก stub ที่ยังไม่ implement แล้วเติม client.beta.sessions.list กับ retrieve session จากนั้นให้ Claude Code เขียนส่วน send events และ stream events เอง โดยอาศัย Claude API skill ที่มากับ Claude Code
  8. ใน developer console ดู session แบบ live ได้ เห็น agent ย่อยแต่ละตัวเป็นเส้นแนวนอน มี context window ของตัวเอง ดู input/output ของแต่ละ event และเวลาที่ tool call ใช้ รวมถึงดู/แก้ memory store ได้ agent มี versioning ย้อนกลับได้

ลำดับขั้นที่ทำในคลิป

  1. ตั้งต้นจาก repo starter (โฟลเดอร์ production-ready agents มีทั้ง starter กับ solution) แล้วรันเซิร์ฟเวอร์ด้วย Bun เพื่อทดสอบ local
  2. เติม endpoint list sessions ด้วย client.beta.sessions.list จาก Anthropic SDK แล้ว sidebar แสดง session ของ workspace
  3. เติม retrieve session (to-do ข้อ 4) ได้ API response ของ get session: agent, tools, Linear MCP, outcomes
  4. ใช้ Claude Code (พร้อม Claude API skill) อ่าน to-do ที่เหลือแล้วเขียน send events กับ stream events เอง
  5. ใน UI สร้าง session ใหม่ เลือก Linear MCP และ memory stores (เรียก create session endpoint)
  6. ส่ง outcome definition event ผ่าน suggestion chip ให้ประเมิน 3 บริษัทตาม rubric แล้วดู agent delegate ให้ sub agent
  7. เปิด developer console ดู session แบบ live: threads ของแต่ละ agent, event, เวลา tool call
  8. ดู/แก้ memory store และ agent version ใน console
  9. ปิดด้วยสรุปว่าไม่ต้องสร้าง agent loop, sandbox fleet, durable storage, auth เอง

  • multi-agent feature เปิดตัว "2 weeks ago" ตามที่ผู้พูดบอก
  • ผู้พูดกล่าวถึง Opus 4.7 ว่าเขียนเอกสารยาวมากได้ (เป็นเหตุผลที่มี span events)

  • เดโมมีบริษัทสมมติ 3 แห่ง: Bridgewell Dynamics, Norwood Automation, Acme Robotics

สิ่งที่นำไปทำต่อ

  • เริ่มจากกำหนด agent + environment แล้วสร้าง session ก่อน ที่เหลือคือส่ง/รับ events
  • ใช้ outcomes (rubric) เมื่ออยากให้ agent ตรวจงานตัวเองซ้ำก่อนส่งผล
  • เก็บ token ของ MCP ไว้ใน credential vault เพื่อไม่ให้เข้า context ของ Claude
  • ข้อมูลที่ห้ามออก perimeter ให้ดู self-hosted sandboxes และ MCP tunnels
  • ให้ Claude Code เขียนส่วน integration ให้ โดยอาศัย Claude API skill แล้วใช้ console debug

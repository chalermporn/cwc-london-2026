สร้างและ deploy แอปบน Google Cloud ด้วย Claude Code ตั้งแต่ศูนย์

Building with Claude on Google Cloud

ผู้พูด: Ivan Nardini (Developer Advocate ที่ Google Cloud (แนะนำตัวเองใน transcript))

เหมาะกับ: developer ที่เคยใช้ Claude Code อยู่แล้วและอยากรู้ว่าจะต่อกับ Google Cloud เพื่อ build, deploy, ตรวจความปลอดภัย และทำ analytics อย่างไร

Ivan Nardini สาธิตสดการสร้างแอปเก็บ feedback ตั้งแต่ wireframe จนถึง production บน Google Cloud โดยสวมห้าบทบาทของทีม (PM, UI/UX, software engineer, security, analytics) ใช้ Claude Code ร่วมกับ plan mode, subagents, MCP server ของ Google Cloud, skills และ plugin ข้อสรุปคือคนไม่ต้องรู้ Google Cloud ลึกก็ ship ได้ถ้าให้ Claude อ่านเอกสารผ่าน MCP

A live demo takes a feedback app from wireframe to production on Google Cloud across five team roles, using Claude Code plan mode, subagents, Google Cloud MCP servers, skills and a plugin.

ประเด็นสำคัญ

  1. ตั้งสถานการณ์ว่าทีม enterprise ปกติมี PM, UI/UX, software engineer, security engineer และคนดู analytics ผู้พูดสวมแต่ละบทบาททีละหมวก แล้วให้ Claude Code เสริมตลอด software life cycle
  2. การใช้ Claude models บน Google Cloud: ตั้งค่า Claude Code ผ่าน application default credentials มี wizard ตรวจ project/region และ pin โมเดล จ่ายตาม token ไม่มี message cap มี provisioned throughput ข้อมูลอยู่ใน project ของตัวเอง ไม่ต้องจัดการ API key และรองรับ multi-region endpoint
  3. บทบาท PM: เขียน CLAUDE.md กำหนดบทบาท แล้วให้ Claude เปลี่ยนภาพร่างเป็น wireframe ภายในไม่กี่นาที
  4. บทบาท UI/UX: ใช้ plan mode ให้ Claude คิดและเสนอสเปกก่อนเขียนโค้ด แล้วแปลง wireframe เป็นสี่หน้าสำหรับ production (รวม dashboard) ผู้พูดบอกว่าในงานจริงอาจเชื่อมกับ Figma
  5. บทบาท software engineer: ใช้ Developer Knowledge API กับ MCP server ที่ให้เอกสารและ implementation guide ที่รีเฟรชทุก 24 ชั่วโมง ออกแบบสถาปัตยกรรมเป็น Cloud Run, Firestore และข้อมูลดิบเข้า BigQuery พร้อม Looker แล้วใช้ official Google Cloud skills ลงมือ deploy
  6. ใช้ subagents ขนานกันหนึ่งตัวต่อ API, data pipeline ใน BigQuery และ dashboard เหมือน sprint ของทีม ใช้โมเดลต่างกันได้ จากนั้นรันเทสต์ สร้าง CI/CD ด้วย Cloud Build กับ Cloud Deploy เปิด PR แล้ว merge ทริกเกอร์ pipeline ไป dev environment
  7. บทบาท security: สร้าง custom plugin ตรวจ input validation และลดสิทธิ์ service account ซึ่ง Claude แก้โค้ด รันเทสต์ซ้ำ เปิด PR ใหม่ และหลังรีวิวใน dev ก็ promote ไป production ผ่าน Cloud Deploy
  8. บทบาท analytics: ใช้ BigQuery MCP server วิเคราะห์ข้อมูล feedback เช่นเวลาที่ผู้ใช้ใช้กรอก แล้วใช้ MCP server อีกตัวสร้าง dashboard ใน Looker ได้เป็นลิงก์เดียวโดยไม่ต้องรู้เครื่องมือเหล่านี้ล่วงหน้า

ลำดับขั้นที่ทำในคลิป

  1. ตั้งค่า Claude Code ให้ใช้โมเดลที่โฮสต์บน Google Cloud ผ่าน application default credentials แล้วใช้ wizard ตรวจ project/region และ pin โมเดล
  2. PM: เขียน CLAUDE.md ระบุบทบาท แล้วให้ Claude เปลี่ยนภาพร่างเป็น wireframe
  3. UI/UX: เข้า plan mode ให้ Claude ร่างสเปก ตรวจ แล้วสั่งสร้างสี่หน้า (landing ถึงหน้าสุดท้าย บวก dashboard) และ push PR
  4. Engineer: ต่อ MCP server ของ Developer Knowledge API กับ Google Cloud skills แล้วให้ Claude ออกแบบสถาปัตยกรรมและสเปก API
  5. สั่ง subagents ขนาน: API, data pipeline ใน BigQuery, dashboard พร้อมเทสต์ แล้วใช้ skill สร้าง CI/CD ด้วย Cloud Build และ Cloud Deploy
  6. Merge PR เพื่อทริกเกอร์ pipeline ไป dev environment
  7. Security: ใช้ custom plugin ตรวจ input validation และลดสิทธิ์ service account แล้วเปิด PR ใหม่ รีวิวใน dev และ promote ไป production ผ่าน Cloud Deploy
  8. Analytics: ใช้ BigQuery MCP วิเคราะห์ข้อมูล feedback แล้วสร้าง dashboard ใน Looker ผ่าน MCP server อีกตัว

ตัวเลข / ข้อเท็จจริงที่ผู้พูดบอก

ตามที่ผู้พูดอ้างในคลิป ไม่ได้ยืนยันกับแหล่งอื่น

  • เอกสารจาก Developer Knowledge API รีเฟรชทุก 24 ชั่วโมงตามที่ผู้พูดบอก
  • ห้าบทบาทในเดโม: PM, UI/UX, software engineer, security engineer, analytics
  • ผู้พูดบอกว่าบน Google Cloud จ่ายตาม token ไม่มี message cap และมี provisioned throughput สำหรับ production
  • คำอธิบายคลิประบุเป้า 'zero to deployed ใน 30 นาที' ส่วนเนื้อหาจริงยาวประมาณ 25 นาที

ประโยคเด่น (ต้นฉบับ)

“You get access to models directly from your dedicated project where you can set your own policy.”

เข้าถึงโมเดลได้ตรงจาก project เฉพาะของตัวเอง และตั้ง policy เองได้

“this mode puts Cloud in a mode where it thinks and it proposes before it starts coding.”

plan mode ทำให้ Claude คิดและเสนอแผนก่อนเริ่มเขียนโค้ด (Cloud ใน transcript = Claude)

“I can parallelize tasks simulating like a team sprint”

แตกงานขนานกันเหมือนทีมทำ sprint ด้วย subagents

สิ่งที่นำไปทำต่อ

  • ถ้าไม่ชำนาญ Google Cloud ให้ต่อ Developer Knowledge API MCP server และ Google Cloud skills แล้วให้ Claude อ่านเอกสารสดแทนการเดา
  • ใช้ plan mode กับงานที่ต้องการให้ตัดสินใจก่อนลงมือ เช่นเปลี่ยน wireframe เป็นหน้า production
  • แตก subagent ต่อส่วน (API, pipeline, dashboard) เพื่อทำงานขนาน แล้วให้เทสต์รันก่อนสร้าง CI/CD
  • สร้าง plugin ตรวจ security ที่ตรงกับข้อกำหนดขององค์กร (เช่น input validation, สิทธิ์ service account) แล้วใช้ก่อน promote
  • ถ้าต้องการ analytics ให้ใช้ BigQuery MCP กับ Looker MCP ทำ dashboard ที่ PM นำไปคุยต่อได้

ข้อควรระวังในสรุปนี้

  • transcript ถอดด้วย Whisper large-v3 ในเครื่อง ไม่ใช่ข้อความต้นฉบับของผู้พูด ชื่อเฉพาะอาจเพี้ยน (Cloud = Claude, 'Anthropix' = Anthropic) และมีประโยค 'I'm Ivan Nardini. I'm the founder of Anthropix' ซึ่งน่าจะเป็นการถอดวนผิด จึงใช้เฉพาะบรรทัดที่แนะนำตัวเป็น developer advocate ที่ Google Cloud
  • ช่วงต้นเดโม PM (ราวนาทีที่ 3-6) transcript วนซ้ำประโยค 'I'm going to use a very simple code' หลายครั้ง เป็นอาการ Whisper hallucination จึงไม่มีรายละเอียดของขั้นตอนนั้น
  • ชื่อผลิตภัณฑ์ Google Cloud (Firestore, Cloud Run, Cloud Build, Cloud Deploy, BigQuery, Looker) บางตัวผู้พูดเรียกกว้างๆ เช่น 'file stores' ที่ผู้สรุปตีความเป็น Firestore จากบริบท
  • ผู้พูดพูดถึงการ merge PR และ plugin แบบรวบรัด ไม่ได้ระบุชื่อ skills หรือ plugin ที่ใช้ ลิงก์ repo/quickstart ที่ว่าจะแชร์ท้าย session ไม่มีใน transcript
  • เดโมเป็นการรันที่เตรียมไว้ล่วงหน้า (ตัดให้เร็ว) ผู้พูดอ้างว่าได้ผลตามที่เห็น ไม่ได้มีการยืนยันอิสระ

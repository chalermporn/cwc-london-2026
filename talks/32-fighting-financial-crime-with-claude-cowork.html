สู้อาชญากรรมการเงินด้วย Claude Cowork: MCP gateway, plugin และ evals

Fighting financial crime with Claude Cowork

ผู้พูด: Stefano Amorelli (Senior Staff Software Engineer ที่ fintech ฝรั่งเศสให้บริการ business banking สำหรับ SME (Whisper เขียนบริษัทเป็น 'Quanto' / 'Conto' ไม่คงที่))

เหมาะกับ: ทีมในองค์กรที่ต้องนำ AI/MCP ไปใช้กับข้อมูลอ่อนไหว และต้องผ่านฝ่าย security กับ compliance

Stefano เล่าว่าทีมสร้างระบบช่วยนักสืบอาชญากรรมการเงินด้วย Claude Cowork plugin ที่ต่อข้อมูลผ่าน MCP gateway ซึ่งจัดการ auth, RBAC และ audit trail ให้ครบ และใช้ evals สร้างความเชื่อมั่น ข้อสรุปคือต้องวาง boundary ด้าน security/compliance ตั้งแต่ต้น แล้ว AI ใช้ใน workflow เสี่ยงสูงได้

A fintech engineer shows a Cowork plugin for financial-crime investigators behind a secure MCP gateway (OAuth, RBAC, audit trail), validated with evals, and argues start with evals and secure data access.

ประเด็นสำคัญ

  1. กระบวนการเดิม: ระบบ alert อัตโนมัติ (ใช้ ML แบบ predictive ไม่ใช่ generative) สร้างเคส แล้วนักสืบเก็บข้อมูลจากหลายแหล่งด้วยมือ จอหลายใบ แท็บเบราว์เซอร์เป็นสิบ ก่อนตัดสินว่าเป็นอาชญากรรมไหม ทีมโฟกัสที่ agentic AI ใน second line of defense ซึ่งผู้พูดบอกว่ายังมีน้อยรายในอุตสาหกรรมที่ทำ
  2. เลือก Opus 4.7 เพราะต้อง reason ข้าม context ยาว ผู้พูดอ้าง benchmark GraphWalks (หาข้อเท็จจริงที่กระจายใน context) ว่า Opus 4.7 นำ แต่ก็บอกว่างานอื่นอาจไม่ต้องใช้รุ่นใหญ่ ใช้ Claude Cowork เป็น UI ให้นักสืบเพราะ onboard คนที่ไม่ใช่สายเทคนิคง่าย
  3. ข้อกังวลเรื่อง MCP กับ security/compliance แก้ได้ด้วยการสร้าง boundary และ harness ที่ปลอดภัย: remote MCP servers แบบรวมศูนย์ OAuth, session token แบบ Paseto อายุสั้น, RBAC, audit trail และคงให้คนตัดสินใจในจุดวิกฤต
  4. สถาปัตยกรรม: Cowork plugin ต่อเข้า MCP gateway (ใช้ ContextForge แบบ open source) ที่ทำ SSO, ตรวจ token, resolve identity, ออก token อายุสั้น และเขียน audit ลงฐานข้อมูลแบบ append-only; ต่อ MCP server ปลายทางที่ deploy บน Kubernetes เรียกตรงไม่ได้ ใช้ streamable HTTP และเขียนด้วยภาษาอะไรก็ได้
  5. RBAC เขียนเป็นไฟล์ Terraform ที่ version ใน GitHub จึง audit ได้ และผู้ใช้จะไม่เห็นด้วยซ้ำว่ามี MCP server ที่ตัวเองไม่มีสิทธิ์ ส่วน tool call ทุกครั้งถูก instrument ด้วย OTel (บวก field เสริม) เก็บใน ClickHouse และดูผ่าน dashboard Grafana ใน production
  6. Cowork render inline widget แบบ interactive ได้ทันที (เร็วกว่า artifact เดิม) ให้นักสืบเห็น dashboard และสั่ง action จาก interface เดียว แทนการสลับหลายเครื่องมือ
  7. โครงสร้าง plugin: แบ่งเป็น sub skills แทน prompt 1,000 บรรทัด มี orchestrator skill เรียก sub skill ตามขั้น มี meta skill ตรวจผลตอนท้ายทุกครั้ง ใช้ XML structured prompt และระบุ MCP server/tool ที่ skill ใช้ไว้ล่วงหน้า
  8. evals วัด 3 อย่าง: เรียก tool ถูกและถูกลำดับ, ไม่ hallucinate (ข้อมูลใน dashboard ต้องอ้างอิงเอกสาร), และ reasoning ถูก (ใช้ LLM as a judge) ช่วยทั้ง engineering, compliance และความเชื่อมั่นของผู้ใช้ เป้าหมายคือขยับจาก human in the loop ไป human on the loop

ตัวเลข / ข้อเท็จจริงที่ผู้พูดบอก

ตามที่ผู้พูดอ้างในคลิป ไม่ได้ยืนยันกับแหล่งอื่น

  • โมเดลที่เลือก: Opus 4.7 (ผู้พูดว่าเป็น frontier model ที่ดีที่สุดสำหรับงาน long-context ตอนนี้)
  • GraphWalks benchmark: วัดการหาข้อเท็จจริงที่กระจายใน context window ผู้พูดบอกว่า Opus 4.7 นำ (ไม่ได้อ่านตัวเลขคะแนน)
  • Paseto tokens: เทคโนโลยีจากปี 2018 ใช้เป็น session token อายุสั้น payload base64 ไม่เข้ารหัสแต่ลงลายเซ็น
  • Stack: ContextForge (MCP gateway), Terraform (RBAC), Kubernetes, streamable HTTP, OpenTelemetry, ClickHouse, Grafana
  • การฟอกเงินทั่วโลก 2-5 ล้านล้านดอลลาร์สหรัฐต่อปี และตรวจพบ/ยึดได้สัดส่วนน้อยมาก (ตามผู้พูด)
  • โปรเจกต์แรกใช้เวลาสร้างไม่กี่สัปดาห์ (ผู้พูดว่า a few weeks) ส่วน use case ใหม่ ๆ นำมาใช้ได้ภายในไม่กี่วัน

สิ่งที่นำไปทำต่อ

  • เริ่มทำ evals ตั้งแต่ต้น เหมือน TDD: วัด tool use, grounding และ reasoning ก่อนขยายระบบ
  • ถ้าต้องต่อ MCP กับข้อมูลอ่อนไหว ให้ใช้ gateway กลางที่รวม SSO, RBAC และ audit trail แทนให้แต่ละ MCP server ทำเอง
  • เขียน RBAC เป็น code (เช่น Terraform) ให้ version และ audit ได้
  • แตก plugin/skill เป็นชิ้นย่อย มี orchestrator กับ meta skill ตรวจผล และใช้ prompt แบบมีโครงสร้าง
  • ทำงานร่วมกับผู้เชี่ยวชาญโดเมนเขียน plugin แล้วให้ทีมอื่นนำ MCP gateway เดิมไปสร้าง plugin ของตัวเอง

ข้อควรระวังในสรุปนี้

  • Transcript มาจาก Whisper large-v3 ที่ถอดเอง: ชื่อบริษัทของผู้พูดสะกดไม่คงที่ ('Quanto' และ 'Conto') ผู้สรุปจึงไม่ระบุชื่อบริษัทแน่ชัด ชื่อผู้พูดตามที่ MC แนะนำ อาจสะกดเพี้ยน
  • ประโยคช่วงต้นมี Whisper ติด loop (ประโยค 'non-profit organization' ซ้ำ) ไม่ใช่เนื้อหาจริงของผู้พูด
  • การอ้างว่า Opus 4.7 นำใน GraphWalks และตัวเลขการฟอกเงิน 2-5 ล้านล้านดอลลาร์เป็นข้ออ้างของผู้พูด ไม่ได้ตรวจกับแหล่งอิสระ
  • ผู้พูดไม่ได้เปิดเผยตัวเลขผลลัพธ์ของ evals หรือข้อมูลลูกค้า (เดโมเป็นวิดีโอที่ปิดบังข้อมูล)

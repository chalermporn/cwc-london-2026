เบื้องหลังสร้าง Claude Design ใน 10 สัปดาห์ด้วยทีมสามคน

Designing with Claude: From prompt to production

ผู้พูด: Dan Carey (Product Manager ผู้นำผลิตภัณฑ์หนึ่งตัวใน Anthropic Labs)

เหมาะกับ: PM, designer และ engineer ที่อยากรู้ว่าทีมเล็กทำงานเร็วอย่างไรเมื่อมี Claude ไม่ต้องมีพื้นฐาน Claude Design มาก่อน

Dan Carey เล่าว่าทีมเล็กใน Anthropic Labs สร้าง Claude Design จากไอเดียถึงเปิดตัวใน 10 สัปดาห์ ด้วยการใช้ prototype แทน PRD ทีมสามคนที่ทุกคนทำได้ทุกบทบาท และวน loop ship-watch-learn ซ้ำ 50 ถึง 100 รอบ ข้อสรุปคือคอขวดย้ายจากการสร้างฟีเจอร์ไปสู่การรู้ว่าควรสร้างอะไร จึงต้องทำ loop ให้สั้นและสร้างเครื่องมือของตัวเอง

A small Anthropic Labs team built Claude Design in about 10 weeks by replacing PRDs with prototypes, keeping a 3-person team with merged roles, and running a ship-watch-learn loop 50-100 times.

ประเด็นสำคัญ

  1. Anthropic Labs เรียกตัวเองว่า bet factory ทีมเล็กทดลองที่ขอบเขตของโมเดล ขยายตัวที่ได้ผล ยุติตัวที่ไม่ได้ผล ผู้พูดบอกว่า Claude Code, Claude Design, MCP, Skills, Claude in Chrome เกิดจาก Labs
  2. ไม่พยายามทำนายอนาคต ใช้ loop ship, watch, learn ซ้ำ คุยกับ user และนักวิจัยทุกวัน ship ทุกวันหรือสองวัน และตอบ feedback ภายในวันถัดไป สำหรับ Claude Design วน loop นี้ราว 50 ถึง 100 รอบใน 10 สัปดาห์
  3. จุดเริ่มคือหลัง Claude Code ทำให้ engineer เร็วขึ้นมาก คอขวดย้ายไปที่การรู้ว่าควรสร้างอะไร designer กับ PM ตามไม่ทัน Nate จึงแฮ็ก prototype จาก Agent SDK เป็น IDE wrapper บางๆ ในสุดสัปดาห์เดียว แล้วโพสต์ใน Slack
  4. ทีมไม่เขียน PRD, vision doc, OKR หรือ press release ล่วงหน้า เพราะเอกสารกำกวมให้คนสองคนเห็นผลิตภัณฑ์ต่างกัน จึงคุยแล้วอัด transcript ส่งให้ Claude Design ขอหลายตัวเลือก prototype ซึ่งแทน PRD ของผู้พูดเอง
  5. ทีมเล็ก: เริ่มด้วยคนเดียวหาประกายความน่าสนใจ เมื่อมีแววขยายเป็นสามคน และอาจถึงห้าคนก่อนเปิดตัว ทุกคนทำทุกบทบาท (engineer คุย user, PM เขียนโค้ด, designer วิเคราะห์ข้อมูล) ช่วยลด coordination overhead
  6. ทีมเร่ง loop ทุกขั้นด้วย Claude: ให้ Claude วิเคราะห์บทสนทนากับ user หาจุดร่วม ใช้ Claude Design ออกแบบ Claude Design เอง (multiplayer และ handoff ไป Claude Code เกิดจากความต้องการของทีมก่อน) และสร้างเครื่องมือ feedback clustering ในหนึ่งบ่าย
  7. บทเรียนจากความผิดพลาด: ชุดควบคุมระดับ pixel สำหรับ power user ได้รับคำชมจากผู้ทดสอบกลุ่มเล็ก แต่ผู้ใช้ส่วนใหญ่เกลียด ทีมถอดออกภายในประมาณหนึ่งสัปดาห์ ได้ข้อสรุปว่าเครื่องมือควรยกระดับ craft ของทุกคน และเปิดให้ export เป็น HTML, CSS, JavaScript
  8. หลังเปิดตัววันศุกร์ ทีม ship การปรับปรุง 62 รายการภายในวันจันทร์ถัดไป และบอกให้ทำ prototype ของสิ่งที่ 'เกือบใช้ได้' เพราะโมเดลรุ่นถัดไปอาจแก้ปัญหาที่วิศวกรรมแก้ไม่ได้ (ปัญหาของ prototype ต้นๆ หายเมื่อ Opus 4.7 ออก)

ตัวเลข / ข้อเท็จจริงที่ผู้พูดบอก

ตามที่ผู้พูดอ้างในคลิป ไม่ได้ยืนยันกับแหล่งอื่น

  • ทีมสามคนเป็นส่วนใหญ่ของการพัฒนา สร้าง Claude Design ในราว 10 สัปดาห์จากไอเดียถึงเปิดตัว
  • วน loop ship-watch-learn ราว 50 ถึง 100 รอบ
  • Claude Design อยู่ใน research preview มาประมาณหนึ่งเดือน ณ วันที่พูด และเพิ่งเพิ่ม token limits เป็นสองเท่าในทุก subscription plan
  • ใน pitch-off ครึ่งหลัง 100% ของ pitch เป็น prototype หรือสไลด์ที่ทำด้วย Claude Design
  • หลังเปิดตัววันศุกร์ ship 62 improvements ภายในวันจันทร์ถัดไป
  • ถอดฟีเจอร์ควบคุมระดับ pixel ที่ผิดทางออกภายในราวหนึ่งสัปดาห์ เทียบกับการวางแผนรายไตรมาสที่จะเสียทั้งไตรมาส
  • ผู้พูดบอกว่าเป็น PM มาเกือบสองทศวรรษ และ prototype เข้ามาแทนการเขียน PRD

ประโยคเด่น (ต้นฉบับ)

“Instead, we try to ship. We watch people use the stuff. We learn what they do.”

แทนที่จะทำนาย เรา ship ดูคนใช้ แล้วเรียนรู้ว่าเขาทำอะไร

“So docs are imprecise. Prototypes, they're more concrete.”

เอกสารกำกวม ส่วน prototype เป็นรูปธรรมกว่า

“you do not want to work on the thing that already works. You often want to prototype the thing that almost works.”

อย่าทำสิ่งที่ใช้ได้อยู่แล้ว ให้ทำ prototype ของสิ่งที่เกือบใช้ได้

สิ่งที่นำไปทำต่อ

  • ครั้งหน้าที่จะเขียน PRD ให้ข้าม แล้วคุยกับเพื่อนร่วมทีมเรื่องทำไมต้องแก้ปัญหานี้และลักษณะของคำตอบที่ดี อัด transcript ส่งให้ Claude ขอ prototype สามแบบ
  • เลือกเครื่องมือภายในที่รอมานาน เช่น feedback clustering แล้วสร้างให้เสร็จในบ่ายเดียว
  • ลองรับ feature request จริงหนึ่งอันจาก user แล้วส่งถึงมือเขาภายใน 24 ชั่วโมง เพื่อค้นหาคอขวดใน deploy และ code review
  • ออกแบบรอบทดลองให้สั้นพอที่จะรู้ว่าผิดทางภายในไม่กี่วัน แทนผูกกับรอบรายไตรมาส
  • ใช้ Claude วิเคราะห์บทสนทนากับ user เบื้องต้น แต่ให้คนเป็นฝ่ายคุยเอง

ข้อควรระวังในสรุปนี้

  • transcript ถอดด้วย Whisper large-v3 ในเครื่อง ไม่ใช่ข้อความต้นฉบับของผู้พูด ชื่อเฉพาะอาจเพี้ยน (ในไฟล์ Claude ถูกเขียนเป็น Cloud ในบางจุด และท้ายคลิปมี 'Collage Design' ซึ่งน่าจะเป็น Claude Design)
  • ชื่อ Nate (designer จาก Claude Code เดิม) มาจาก transcript เท่านั้น ไม่มีนามสกุล
  • ข้อความกล่าวถึงการเชื่อม design tool ต่างๆ เข้ากับ Claude Code 'สัปดาห์นี้หรือสัปดาห์หน้า' เป็นแผนที่ผู้พูดบอก ไม่ยืนยันว่าเกิดขึ้นแล้ว
  • ตัวเลขทั้งหมด (10 สัปดาห์, 62 improvements, 50 ถึง 100 รอบ) เป็นข้ออ้างของผู้พูด ไม่ได้ตรวจสอบกับแหล่งอื่น
  • ประโยคเรื่อง Nate โพสต์ใน Slack ถูกตัดทอนและมีข้อความแหว่งในต้นฉบับ รายละเอียดบางส่วนจึงอาจขาด

รีดประสิทธิภาพ Claude Platform: caching, context engineering, advisor strategy

Getting more out of the Claude Platform

ผู้พูด: (ไม่ได้ระบุชื่อ) (product manager ทีม platform ที่ Anthropic (แนะนำตัวเอง ไม่ได้บอกชื่อ) และเป็น 'CEO ของ HeroCorp' ในเดโม); Ben (CTO ของ HeroCorp (ตัวละครในเดโม) ขึ้นมาควบคุมเครื่องเดโม)

เหมาะกับ: นักพัฒนาที่มี agent แล้วหรือกำลังจะขึ้น production และอยากลดต้นทุน/latency โดยคุณภาพไม่ตก (รู้จัก tool use และ Claude API เบื้องต้น)

เซสชันปิดงานที่เดโมเอเจนต์ dashboard ของบริษัทสมมติ HeroCorp ลดต้นทุนทีละขั้น: เปิด prompt caching, ทำ context engineering (tool search, programmatic tool calling, compaction) แล้วสลับไปใช้ Sonnet คู่กับ Opus เป็น advisor ผู้พูดสรุปว่าต้นทุนลดลงกว่า 10 เท่าจากจุดเริ่มต้นโดยไม่เสียคุณภาพ ข้อสรุปหลักคือถ้าทำอย่างเดียวให้ทำ prompt caching

A live demo that cuts an agent's cost step by step: prompt caching, then context engineering (tool search, programmatic tool calling, compaction), then Sonnet with an Opus advisor. If you do one thing, do prompt caching.

ประเด็นสำคัญ

  1. prompt caching ให้ผลสามอย่างตามที่ผู้พูดบอก: ส่วนลด 90% สำหรับ token ที่ cache, rate limit ไม่นับ cached token (hit rate 80% เท่ากับ limit ใหญ่ขึ้นราว 5 เท่า) และ time to first token ลดลง เป้าหมายสำหรับ agent คือ 80% ขึ้นไป ลูกค้าอย่าง Replit, Cursor, Perplexity, Claude Code ได้ 90%+
  2. ขั้นแรกคือรู้ cache hit rate ของตัวเอง ตอนนี้ console มี analytics ของ prompt caching ข้าง cost/usage และเพิ่งเพิ่มฟีเจอร์บอกว่าทำไม cache แตก ข้อผิดพลาดที่เจอบ่อยคือใส่ timestamp ไว้ใน system prompt เพราะ token ต้องตรงกันทุกตัว ทางเริ่มคือ auto caching (เปลี่ยนโค้ดบรรทัดเดียว) หรือ Claude API skill ที่ช่วยปรับลำดับ prompt
  3. เดโม HeroCorp: เริ่มที่ hit rate 0 ต้นทุนราว 31 ปอนด์ต่อการโหลด พอเปิด caching ได้ราว 58% hit rate ต้นทุนลดเกือบครึ่ง โดย output เหมือนเดิมเพราะ caching ไม่กระทบความฉลาด แต่ context เต็มเมื่อมี 5 OKR จึงต้องทำ context engineering
  4. Tool search: ส่งให้โมเดลแค่ tool สำหรับค้น แล้วโหลดนิยาม tool จริงเมื่อต้องใช้ ผู้พูดบอกว่า Lovable ลดการใช้ token รวม 10% และผลลัพธ์ดีขึ้นด้วย ในเดโมเห็น schema ของ tool ใหญ่ๆ (เช่น 14,000 token) ไม่ถูกโหลดจนกว่าจะเรียกใช้
  5. Programmatic tool calling: ให้ Claude เขียนสคริปต์ Python เรียก tool แล้วกรองผลก่อนส่งกลับโมเดล ในเดโมผลจาก Gong ที่ยาวมากถูกย่อเหลือเฉพาะ aggregate sentiment ผู้พูดบอกว่า Quora ใช้กับ HTML โดยตัดส่วนไม่เกี่ยวข้องและประสิทธิภาพดีขึ้น
  6. Compaction: เมื่อถึง threshold (เดโมตั้ง 400K) ระบบสรุป context ด้วย prompt ที่ปรับเองได้ แล้วคุยต่อ ให้ความรู้สึกว่า context ไม่จำกัด ผู้พูดแนะนำเริ่มที่ 400K-500K และบอกว่าขึ้นกับโมเดล ผู้พูดอ้างว่า Hex ใช้แล้วโค้ดง่ายขึ้น ต้นทุนในเดโมลดเหลือราว 11 ปอนด์
  7. Advisor strategy: ให้ executor เป็น Sonnet/Haiku แล้วเรียก Opus เป็น advisor เฉพาะเมื่อเจอเคสยาก เปรียบเหมือน junior จับคู่ senior ผู้พูดบอกว่า Bolt ใช้แล้วได้การตัดสินใจเชิงสถาปัตยกรรมดีขึ้นในงานซับซ้อน และงานง่ายไม่มี overhead เพราะไม่เรียก tool ในเดโม Sonnet มองสัญญา Metropolis เป็นสีเขียว แต่ Opus อ่านลึกแล้วพบว่าเป็นสีแดง (ตัวละครที่ลูกค้าต้องการไม่ว่างวันงาน)
  8. ข้อสรุป: ทำ prompt caching ก่อน (รู้ hit rate, ใช้ Claude API skill) แล้ว context engineering (คัดว่า tool ใดถูกส่ง, ผลลัพธ์ใดถูกส่งกลับ, compact เมื่อยาว) แล้ว advisor strategy และ 'ดู transcript ของ agent เสมอ' ผู้พูดบอกด้วยว่ามีฟีเจอร์ที่เพิ่งเปิดตัวใน 24 ชั่วโมง เช่น automatic prompt caching และ Claude Platform บน AWS

ลำดับขั้นที่ทำในคลิป

  1. เปิดเดโม dashboard ของ HeroCorp ดู developer console และ transcript ของ agent ซึ่งดึงข้อมูลจาก web, Slack, Gong, Jira
  2. เช็ก prompt cache hit rate (เริ่มที่ 0) แล้วเปิด prompt caching ได้ราว 58% hit rate และต้นทุนลดเกือบครึ่ง (31 ปอนด์เป็นเริ่มต้น)
  3. ใส่ context engineering ทีละชั้น: tool search (ไม่โหลด schema จนกว่าจะเรียกใช้), programmatic tool calling (สคริปต์กรองผลจาก Gong เหลือ aggregate sentiment), compaction (threshold 400K พร้อม prompt สรุปของตัวเอง) ต้นทุนเหลือราว 11 ปอนด์
  4. เปลี่ยน executor เป็น Sonnet 4.6 และตั้ง Opus 4.7 เป็น advisor ตรวจสัญญา Metropolis ที่ Sonnet ประเมินเป็นเขียว แต่ Opus แก้เป็นแดง
  5. ปิดด้วยการกดปุ่ม 'save the Metropolis contract' ในแดชบอร์ด และสรุปลำดับ caching, context engineering, advisor

ตัวเลข / ข้อเท็จจริงที่ผู้พูดบอก

ตามที่ผู้พูดอ้างในคลิป ไม่ได้ยืนยันกับแหล่งอื่น

  • prompt caching: ส่วนลด 90% สำหรับ token ที่ cache; hit rate 80% = rate limit ใหญ่ขึ้นราว 5 เท่าในทางปฏิบัติ (ตามผู้พูด)
  • เป้า cache hit rate 80%+ สำหรับ agentic app; Replit, Cursor, Perplexity, Claude Code 90%+
  • เดโม: ต้นทุนราว 31 ปอนด์ที่ hit rate 0 -> ราว 11 ปอนด์หลัง caching + context engineering -> ลดต่ออีกด้วย Sonnet 4.6 + Opus 4.7 advisor; ผู้พูดสรุปว่าลดจากจุดเริ่มกว่า 10 เท่า
  • cache hit ในเดโมหลังเปิด caching ราว 58%; cache write 172 tokens แล้ว cache hit 172 tokens ในตัวอย่างที่ซูม
  • Compaction threshold ในเดโม 400K token; แนะนำเริ่มที่ 400K-500K แล้วปรับตามโมเดล
  • ขนาด tool schema ในเดโม: hero retention metrics ราว 14,000 token, hero list 6,100, อีกตัว 9,300
  • Lovable: ลด token รวม 10% ด้วย tool search (ตามผู้พูด)
  • โมเดลในเดโม: Opus 4.7 (เริ่มต้น) แล้ว Sonnet 4.6 เป็น executor + Opus 4.7 เป็น advisor

สิ่งที่นำไปทำต่อ

  • วัด prompt cache hit rate ของ agent ตัวเองก่อน (console analytics) ถ้าต่ำให้เริ่มจาก auto caching หรือ Claude API skill
  • อย่าใส่ข้อมูลที่เปลี่ยนตลอด เช่น timestamp ไว้ต้น system prompt เพราะทำให้ cache แตกทั้งหมด
  • เปิดอ่าน transcript ของ agent เป็นประจำ เพื่อเห็นว่าโมเดลเห็นอะไรจริงและมีของไม่จำเป็นอะไรปนอยู่
  • ถ้า tool เยอะหรือผลลัพธ์ยาว ลอง tool search, programmatic tool calling และตั้ง compaction threshold ที่ 400K-500K
  • ลองจับคู่ executor ราคาถูก (Sonnet/Haiku) กับ Opus advisor แล้ววัดคุณภาพและต้นทุนเทียบกับรัน Opus ล้วน

ข้อควรระวังในสรุปนี้

  • แหล่งคือ transcript จาก Whisper large-v3 ที่ถอดเอง ไม่ใช่ YouTube caption: 'Cloud' = Claude, 'cash/cashed' = cache/cached, 'CacheSkill' และ 'Cloud API skill' ควรเป็น Claude API skill
  • ผู้พูดหลักไม่ได้บอกชื่อใน transcript จึงใส่ชื่อไม่ได้; Ben เป็นตัวละคร CTO ในเดโม (อาจเป็นคนจริงบนเวที แต่ transcript ไม่ยืนยัน)
  • ผลลัพธ์ทั้งหมด (ลด 10 เท่า, 90% discount, Lovable 10%, Hex, Bolt, Quora) เป็นข้ออ้างของผู้พูดและเดโมสมมติ ตรวจสอบเองไม่ได้ ตัวเลขต้นทุนเป็นสกุลปอนด์ต่อการโหลด dashboard ในเดโมเท่านั้น
  • ตัวเลขจาก ASR เช่น 58%, 172 tokens, 14,000/6,100/9,300 ควรตรวจกับวิดีโอ
  • ผู้พูดบอกว่าหลายฟีเจอร์ (cache break analytics, automatic prompt caching, Claude Platform บน AWS) เพิ่งเปิดตัวใน 24 ชั่วโมงก่อนงาน ไม่ได้ตรวจสถานะปัจจุบัน
  • Advisor strategy ไม่ได้ระบุชื่อ tool/พารามิเตอร์ API ใน transcript จึงไม่ได้ใส่ในขั้นตอน
